New `vegafactory dispatch enable|disable|status|run`: a machine that works the board with nobody at the keyboard. It refuses every verb but `disable` unless the org control room's `dispatchers.md` names this machine, so enrolling and standing a machine down are both control-room PRs. `enable` checks the row, the harness hooks on both tools, a real `claude -p` and `codex exec` answering on their subscriptions, and the GitHub App key, then installs the launchd (macOS) or systemd (Linux) unit; a failed check installs nothing and names what to fix. `status` prints the board, this machine's recent runs and any issue it has parked for a person, and `run --once` makes a single pass. The roster is re-read every pass, so deleting a row stands a running machine down at the next poll with nothing to log into.

The roster is refreshed from the control room and verified before every pass, so a row removed upstream stands a running machine down at its next poll and a copy edited on the machine itself authorises nothing; a roster that cannot be refreshed refuses rather than falling back to what is on disk. A run takes the issue's claim as the App before it launches and gives it back on every way out — a planning or shipping run holds it for the whole run, an implement run hands it to the session it starts — so another machine's poll sees the work is taken. Stopping the dispatcher, de-listing it or running `disable` ends the runs it started, saves their work and releases their claims. The three-runs-at-once and one-merge-at-a-time caps are per machine.

Identity is the VegaFactory GitHub App. The dispatcher mints an hour-long installation token from the private key on the machine (`~/.vegastack/vegafactory-app.pem`, moved by `VEGAFACTORY_APP_PRIVATE_KEY_FILE`; `VEGAFACTORY_APP_ID` names another org's App), narrowed to the one repository, kept in memory and handed to `gh` in that child's environment only — never written down, never printed, never on a command line. A token is re-minted a few minutes before it expires, so a dispatcher that has been up for a month still writes, and the key file is re-checked on every mint: a regular file, not a link, owned by the account running the dispatcher, readable by nobody else. A missing or loose key refuses with the path to fix and never falls back to a person's token. Each dispatched run gets that same short-lived token in its environment as `GH_TOKEN`, and never the path to the key, so everything a run posts is authored by `vegafactory[bot]`: a comment from the App counts as a claim holder, a claim release and the author of a work artifact, and counts for nothing as an ack, a stop, a correction or a "ship it" — a run cannot consent to its own work. The App's Contents permission is read-only, so a dispatcher box needs a git credential of its own for pushes; dev-setup's `references/github-app.md` states both halves.

Each dispatched run starts with `VSK_ASK_ROUTE=issue`, so a round of questions goes to the issue and waits there for the operator instead of reaching for a question tool nobody is watching, and the plan's `**Independent groups:**` block is now read rather than merely recorded: the dispatcher is what runs disjoint sibling sub-issues at the same time.

The loop reads the board every two minutes through the issue cache, so an unchanged issue is nearly free, and runs at most three steps at once: an operator comment on `waiting-on-operator` is a follow-up, `planning` is a plan (a `large` issue splits into sub-issues under an `epic`), `queued` is an implement run that reviews and hands back on `ready-to-ship`, an operator comment on `ready-to-ship` is either corrections or — when a line of it is only "ship it" — a ship, "stop" saves the work, pushes it and releases the claim, and a subscription limit does the same with a note and retries after the reset. A ship is never taken from the words alone: the dispatcher relays the operator's own comment as an ack and then asks the same question `vegafactory issue check --for ship` asks, so "do not ship it" and "ship it after fixing X" are corrections, and a relayed ack that does not validate ships nothing. Every run that does not finish — a failure, a twenty-minute timeout, a subscription limit, a stop — saves its work, pushes it, releases the claim, says why on the issue and puts the state label back where it found it, so no run can leave an issue `in-progress` with nobody on it; one that crashed before it could is picked back up once its claim goes stale. A stand-down touches a worktree only while this machine's claim holds it, and only on the issue's own branch: one left on the default branch, on another issue's branch or on a detached head is refused before anything is committed. One dispatcher runs per machine — a second refuses while the first is alive, and a crashed one's lock is taken over — and every claim carries that process's own id, so a service and a pass run by hand on one box cannot read each other's claims as their own. An operator's "stop" reaches a run that is already going: its process group is ended, waited for, and the issue handed back with the operator's own reason. A signal does the same for every run at once, immediately, rather than after the current two-minute sleep, and `disable` stops the runs the service had started — proving each record is still its own process before signalling it, so a reused pid is never someone else's process. Each trigger runs once, whatever the run settled as; a failed step backs off from when it stopped and is parked for a person after three tries, where `status` names it. The caps, the retry waits and the subscription-reset waits are all per machine, and an implement run's claim hand-over leaves a seconds-wide window — a fleet-wide lease closes both, and until it lands the docs say so plainly. A queued issue with an open blocker is left alone, and only a person with write access can supply the comments the loop acts on — the plan whose file sets let two agents run at once, the evidence that opens the ship window, and the words themselves. An issue with a fresh claim is skipped, a step is killed after 20 minutes, merges go one at a time, tasks inside an issue run in order, and two code runs happen together only for sibling sub-issues whose parent epic's **acked** plan declares disjoint file sets — the ack's own hash binds it, the plan has to pass `plan-lint`, every path is canonicalized so `src/../src/x` and `src/x` are one file, and a traversal, a glob or an absolute path makes the whole set uncheckable — never on generated code, migrations, lockfiles or `package.json`. Every child run goes through the subscription check, so an API-key variable in the environment refuses the command, and each run's own output is bounded and recorded on the machine rather than posted to the issue.
