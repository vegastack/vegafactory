New `vegafactory review <n>`: the cross-tool review in one command. It builds the packet (the brief's acceptance criteria, the plan's tasks, the diff stat, the changed files and `git diff -U5` against the base), starts the *other* tool read-only in the issue's worktree with that packet on stdin — `codex exec -s read-only --output-schema …` or `claude -p --tools Read,Grep,Glob --output-format json --json-schema …`, on the subscription with parent-app variables dropped — validates the JSON verdict and findings it returns, and posts the one review comment itself, so the reviewer never writes to GitHub. A fix round resumes the same reviewer session on the machine that ran it and sends only the fix diff and the open finding ids; on another machine a fresh reviewer gets the previous findings from the comment. At most three rounds per **cycle**: after the third the command hands back, and committing the fixes (or editing the brief or plan) opens the next cycle at round 1 with the open findings carried over, the comment keeping one line per closed cycle. Nothing was reviewed if an input moved while the reviewer ran: the head, the worktree and the brief and plan hashes are re-read before the comment is written, and a change means a hand-back with nothing posted. Where the other tool is missing, `--record <file>` lets this session's own axis review land through the same bindings and validation, marked `mode=same-tool` in the comment and the ship record. It is allowed only when that tool is proven unavailable — not installed, not runnable, or not signed in — or when the operator allowed it for that head in a line of their own (`accept same-tool review @ <sha7>`), and the reason is part of the comment. Big (over ~800 lines or ~15 files) or `risky` diffs split into two parallel reviewers whose findings merge. A stuck reviewer is killed after 60 minutes and retried once; a failed review is always a hand-back, never a skipped review. Flags: `--base` (round 1 only — the base is fixed for the cycle and always resolved to a commit id before it reaches git), `--reviewer`, `--resume`, `--json`, `--dry-run`. The packet wraps the issue text, the plan, the file names and the diff in per-run boundaries marked as data, so a line of the diff cannot give the reviewer instructions, and a review comment counts only when a person with repository write access posted it and its marker agrees with its findings JSON. The comment is upserted under the issue lock, so a concurrent round edits the one comment instead of posting a rival. Child runs now drop the parent session's variables for **both** harnesses, whichever one is the parent. The never-flag list that governs a review is read from the base commit, so a branch cannot suppress its own findings; each round's findings are re-checked by the axis group that owns them; the review comment and the local session state are written in one locked step; and the reviewer's model and effort come from the worktree under review — a preference, unlike the ship guard's committed policy. Exit 0 clean, 2 needs-fixes or hand-back, 1 error. dev-review is rewritten around it, with the same-tool fresh-subagent review kept only as the labelled fallback when the other tool is missing. The `review:` knob is **retired** — reviews always run cross-tool, so there is nothing to choose: dev-setup no longer asks for it, the profile and control-room templates no longer carry it, and it is gone from the policy resolver's knobs and lockable keys. A profile that still carries an old `review:` line keeps working: the line is ignored, so control-room resolution and `vegafactory sync` never block on it, while `review <harness> <model> <effort>` stays this stage's harness-policy line.

The `harness-policy:` grammar gains a literal `default` in the model position — `<stage> <agent> default|<model id> <effort>` — meaning "the tool's own model, this effort": no model flag is passed, so a subscription account never fails on a pinned id it cannot serve, while the effort still applies. A pinned id keeps working. The effort is now checked against the levels each harness accepts, so a typo is caught in the profile instead of at run time.

`vegafactory ship check <n>` now enforces the promise: the commit that would merge must carry a clean review comment from a reviewer with repository write access, or the operator's own comment accepting what that review left open, naming the round and the head (`accept review round 3 @ abc1234`) — an agent-written artifact or a bot comment never counts. A reviewer's verdict is derived from its own findings — in a fresh run and in a comment read back — and a finding a group was asked to re-check keeps the id the operator already read. A review is bound to the brief and plan it read, so editing either makes it stale for both the command and the ship gate, while ticking a plan checkbox does not; the command refuses to review a dirty worktree. The ship gate also requires the review's base to be in the repository's own default branch (read from GitHub, with its remote ref present), refuses when two trusted review comments disagree at one round, and takes the acceptance only at the capped round, as a line of its own.
